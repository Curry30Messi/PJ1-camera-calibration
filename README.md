# PJ1 相机标定

仓库地址：https://github.com/geniusLouis/PJ1-camera-calibration

智能信息处理课程六人协作项目。使用 OpenCV，对标定板2左相机的4张图进行单目标定，方格边长30mm，图像1024×576。截止2026年11月18日23:59。

此仓库起始版本包含报告框架和4张输入图片，实验代码、参数和结论由负责人依次完成。模板中的“待填写”不代表已经有实验结果。

## 将本地仓库发布到 GitHub

首次发布由仓库所有者完成一次即可。推荐使用 GitHub Desktop，无需先在网页创建空仓库：

1. 安装并登录 GitHub Desktop：https://desktop.github.com/ 。
2. 选择 File → Add Local Repository（添加本地仓库）。
3. 选择当前 PJ1-camera-calibration 文件夹，不要选择它的父目录，也不要新建一个空文件夹。
4. 点击 Publish repository，仓库名称填 PJ1-camera-calibration，保留 Keep this code private，发布到个人账号。
5. 发布完成后选择 Repository → View on GitHub，确认页面中有 README.md、“报告”和“代码”。原始4张图片位于“代码/数据”。
6. 在网页 Settings → Collaborators 邀请其他5人的GitHub账号，成员接受邀请后才能推送。

GitHub Desktop会将现有目录和提交记录一起发布，无需重新上传或手动创建两个文件夹。若已在网页创建同名仓库，先停止使用上述Publish流程，改为给本地仓库配置该空仓库的origin并push，避免创建两个仓库。

发布后的成员操作仍按下方接力流程：第一次clone，以后开始前pull，完成后commit和push。Word第1章至第6章各从新页开始，成员只填写自己的章节。

## 开始协作前

仓库建议设为 Private。仓库所有者在 GitHub 的 Settings → Collaborators 添加另外5位成员，成员接受邀请后才能直接 push。需要每个人的 GitHub 用户名才能发出邀请；姓名不能用于确定账号。仓库创建和邀请完成后，大家使用仓库页面的 Code 按钮复制实际 HTTPS 地址。不要把GitHub密码或访问令牌写进命令、代码或报告。

每人安装 Git 并准备 Python。GitHub HTTPS 登录可使用 Git Credential Manager、浏览器授权或个人访问令牌；普通账号密码不能用于 Git push。首次配置自己的提交身份：

```bash
git config --global user.name "你的名字"
git config --global user.email "你的GitHub提交邮箱"
```

也可以使用 GitHub Desktop：Clone repository → Fetch origin / Pull origin → 修改文件 → Commit to main → Push origin。

## 第一次参加项目

只需要 clone 一次。将下方实际仓库地址替换为 GitHub 页面复制的地址：

```bash
git clone https://github.com/geniusLouis/PJ1-camera-calibration.git PJ1-camera-calibration

```

后面每次继续工作，都进入自己已有的这个目录，执行 pull，不要反复 clone，也不要用旧的下载ZIP覆盖仓库。

## 每个人的接力操作

采用main分支顺序接力。前一位push成功并通知交接后，下一位再开始编辑Word；同一时间只有一人修改报告。其他人可以阅读资料和准备实验，但不要同时保存、提交报告。

开始前确认 `git status` 没有自己的未提交修改，关闭打开的旧Word，再拉取：

```bash
git switch main
git pull --ff-only origin main
```

然后打开“报告/组X-相机标定.docx”，仅填写自己章节；按本章指定位置插入关键代码、全部实验汇总结果、图片和分析。保存Word并关闭程序，以免生成锁文件或误传未保存版本。

每个成员在提交前完成以下事项：

1. 将自己的脚本和实验输出放入“代码”，保留前人文件。
2. 将自己的重要代码、结果表与图片完整放入Word；不只写“见代码”或“见文件”。
3. 把本章待填写提示替换为正式内容，原有章节保留。
4. 在本章交接记录写明脚本入口、运行命令、参数文件和下一人所需文件。
5. 在下方“运行记录”追加自己脚本的实际命令及必要设置。
6. 检查状态和变更，再提交、上传：

```bash
git status
git diff --stat
git add README.md "代码" "报告"
git commit -m "姓名：完成第N章实验和报告"
git push origin main
```

commit消息换成本人姓名和章号。确认push成功后，告知下一位最新提交号（`git log -1 --oneline`）及完成内容，下一位先pull再工作。图片和结果也要push，不能只上传Word。Word中的截图不能代替角点和参数文件。

## 遇到冲突或push失败

- push被拒绝时先停止，保存本地文件备份，再和当前编辑者确认；不要 `push --force`，不要用旧Word覆盖远端。
- pull报本地修改或无法快进时，先检查 `git status`。保留自己的修改，确认对应负责人和版本后再处理。
- Word是二进制文件，Git不能可靠合并两人对同一Word的修改。若冲突，保留两个版本，确认哪份为主版本，再由各作者把自己的新增内容补入，正常提交。
- 无权限push：确认已登录正确账号并接受协作者邀请。
- Python路径采用相对脚本位置的路径，不写入个人电脑绝对路径。
